# Backup Verification（バックアップは「表示」ではなく「数」で確認する）

同期ツールの成功表示は、バックアップが存在する証拠にならない。
**件数かハッシュで数えるまで、バックアップは存在しないものとして扱え。**

## Trigger（この操作をするときは必ず読む）

- バックアップ・同期の仕組みを新規に作る、または既存のものを変更する
- `.gitignore` / `.rsync-filter` など**除外パターン**を編集する
- クラウドストレージ（Google Drive / iCloud / Dropbox / OneDrive）へファイルを送る
- 「バックアップされている」「同期されている」を前提に、**元データを消す・移す・追跡から外す**

最後の1つが一番危ない。**検証を挟まずに元を動かすと、その瞬間にデータがどこにも無くなる。**

## 絶対ルール

### 1. 完了は、送信側の表示ではなく受信側の件数で判定する

「同期しました」「最新の状態です」「アップロード完了」は**すべて送信側の主張**であって、
受信側に物が在ることの証明ではない。必ず**受信側を数える**。

```bash
# 悪い: アプリの画面を見て「できた」と判断する
# 良い: 受信側の実数を出す
rclone check <ローカル> <リモート> --one-way   # ハッシュ照合。差分0を確認
rclone size <リモート>                          # オブジェクト数とバイト数
git -c core.quotePath=false ls-files | grep -c <パターン>   # 追跡されている実数
```

数が合わないなら、**表示が何と言っていても失敗している。**

### 2. 除外パターンを書いたら、除外された実数を数える

`.gitignore` に書いた瞬間は「無視するつもり」でしかない。
**意図した対象だけが除外されたか**、**意図せず巻き込んだものが無いか**を数える。

`.gitignore` は**既に追跡中のファイルには効かない**。追加しただけでは止まらない。
`git ls-files` で実際に外れたかを必ず確認する。

### 3. 検証が通る前に、元データを動かすな

順番は例外なくこれ。

1. コピーする
2. **受信側を数えて一致を確認する**
3. そのあとで元を消す・移す・追跡から外す

2 を飛ばすと、1 が失敗していた場合に**どこにもデータが無い時間**ができる。

### 4. 検証を仕組みに埋め込む

人間が毎回思い出す方式は破綻する。**同期スクリプトの中に検証を入れ、
一致しなければ異常終了させる。** 検証を別コマンドにすると、誰も打たなくなる。

実例: `~/.claude/scripts/sync-university-pdf.sh`
（`rclone copy` のあとに必ず `rclone check` を走らせ、差分があれば exit 1）

## Burn Log

### 2026-08-16 ... 同じ日に2回踏んだ

**1回目: `.gitignore` が全画像を除外していた**

Obsidian Vault で毎時 `vault backup` を14ヶ月回していた。
`.gitignore` に `*.png` `*.jpg` `*.svg` があり、**画像533枚・141MBが1枚もバックアップされていなかった。**
noteのヘッダー画像も、図の記入例も、全部。Mac が飛べば消えていた。
毎時コミットが1,247件積まれていたので、「バックアップは回っている」と信じ切っていた。

**2回目: Google Drive が「最新の状態です」と言いながら0バイト**

大学の講義PDF 588MB を Drive デスクトップ版のマウントに `rsync` でコピーした。
Drive アプリは「ファイルは最新の状態になっています」と表示。ウェブでもフォルダが見えた。
`rclone size` で数えたら **Total objects: 0 / Total size: 0 B**。
フォルダだけ作られ、中身は1バイトも上がっていなかった。
CLI から書いたファイルを macOS の FileProvider が検知し損ね、
Drive は同期済みと判定して**二度と再試行しない状態**に入っていた。

このとき、もし表示を信じて先に `git rm --cached` を打っていたら、
**PDF 588MB がどこにもバックアップされていない状態**になっていた。

**共通する構造**

どちらも「バックアップされている」と「バックアップされていることを確認した」を
同じものとして扱っていた。**表示を読んで、中身を数えていなかった。**

これは `~/.claude/rules/coding-style.md` の Self-Verification（最後の grep を走らせろ）と
同じ原則。「ルールを書いた」と「ルールが守られている」が別の状態であるように、
「同期を設定した」と「データが向こうに在る」も別の状態。

**対処**

- `rclone` に移行（`rclone check` でハッシュ照合できる。Drive デスクトップは検証手段が無い）
- 同期スクリプトに検証を埋め込み、不一致なら exit 1
- 除外パターンを触ったら `git ls-files` で実数を数える
