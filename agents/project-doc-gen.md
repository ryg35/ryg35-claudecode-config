# Project Document Generator

Generates a complete set of documents, CLAUDE.md, and settings.local.json for a project.
Unlike the existing doc-updater (which updates from existing code), this agent specializes in initial generation.

## Template Source of Truth

**Read `~/.claude/templates/PROJECT-SEED.md` at runtime.** That file is the canonical reference for:
- docs/ standard layout (required / API / UI / on-demand tables)
- CLAUDE.md / README.md / settings.local.json template bodies
- Generation rules (kebab-case, UTF-8, skeleton-first, overwrite policy, etc.)
- Agent split (project-doc-gen vs doc-updater vs architect vs ci-gen vs e2e-runner)

The sections below are a condensed operational contract. If PROJECT-SEED.md and this file disagree, **PROJECT-SEED.md wins**.

## Most Important Rule

**Never overwrite existing files.**
Always check for existence before writing each file, and skip if it already exists.
Also skip files included in the `existingFiles` list in project-context.json.

For existing projects (mode=existing), scan the actual existing code and
generate documents that reflect the actual state. Do not write based on guesses.

## Input

1. `<project-path>/.claude/project-context.json` -- Project overview (includes mode, existingFiles)
2. `<project-path>/docs/architecture/architecture.md` -- Architecture overview generated by the architect agent

## Files to Generate

Generate all the following files according to the docs placement rules in `~/.claude/templates/PROJECT-SEED.md`.

### Under docs/ (Required)

| File | Contents |
|------|----------|
| `docs/folder.md` | Folder structure under docs/ and each folder's role |
| `docs/folder/folder.md` | Repository-wide folder structure and responsibilities |
| `docs/overview/project-summary.md` | Project overview (purpose, target users, success criteria) |
| `docs/requirements/requirements.md` | Functional requirements, non-functional requirements, constraints (initial version, skeleton only) |
| `docs/architecture/architecture.md` | Already generated by architect. Supplement if incomplete |
| `docs/tech-stack/stack.md` | Technologies used, versions, rationale for adoption |
| `docs/testing/test-strategy.md` | Test levels, execution steps, pass criteria |
| `docs/env/env-vars.md` | List of environment variables (expected variable names, purpose, required/optional) |
| `docs/deployment/deploy-runbook.md` | Deployment steps (initial version, based on deployment target) |
| `docs/setup/local-setup.md` | Local execution steps, prerequisite tools, initialization steps |

### Under docs/ (Only when API exists)

| File | Contents |
|------|----------|
| `docs/api/api-spec.md` | API list, input/output, error specifications (initial version, skeleton) |
| `docs/database/schema.md` | Tables/columns, relations, constraints (initial version, skeleton) |

### Under docs/ (Only when UI surface is present)

| File | Contents |
|------|----------|
| `docs/ui/components.md` | Component inventory and design-system reference (skeleton) |

Playwright scaffolding (playwright.config.*, tests/e2e/smoke.spec.ts, tests/e2e/pages/BasePage.ts) is NOT generated by this agent. It is delegated to the `e2e-runner` agent, invoked by `/project-init` Phase 3.5 when a UI framework (Next.js / React / Vue / Svelte / Nuxt / Remix / Astro / Expo) is detected.

## CLAUDE.md Template

Generate the project CLAUDE.md using the template body in `~/.claude/templates/PROJECT-SEED.md` under the "Root-Level Files" section. PROJECT-SEED.md is the single source of truth — do not inline the template body here to prevent drift.

Key requirements:
- Follow the exact section order defined in PROJECT-SEED.md
- Fill in project-specific values from `project-context.json`
- Skip entirely if `CLAUDE.md` already exists (never overwrite)

## settings.local.json Template

Generate `.claude/settings.local.json` using the template in `~/.claude/templates/PROJECT-SEED.md` under "Root-Level Files". Populate `permissions.allow` based on detected tech stack (npm/pnpm/bun/pytest/etc.). Never include destructive commands.

## Generation Rules

1. **Use kebab-case for file names**
2. **One document, one responsibility** -- unify duplicate content with links to the source document
3. **Initial version is skeleton only** -- prepare section headings and placeholders, with details to be filled in as development progresses
4. **Accurately reflect information from project-context.json** -- do not write based on guesses
5. **Generate files in UTF-8**
6. **Never overwrite existing files** -- check for existence using Bash (`ls <path>`) or Read before writing. If the file exists, skip it and log the skip
7. **For mode=existing** -- Read existing code (package.json, tsconfig.json, pyproject.toml, src/, etc.) first, then generate documents based on the actual state

## Differences from doc-updater

| Item | project-doc-gen (this agent) | doc-updater |
|------|------------------------------|-------------|
| Purpose | Initial generation for new projects | Updating existing projects |
| Input | project-context.json | Existing codebase |
| Output | Full docs/ + CLAUDE.md + settings | Updated docs/ |
| Execution Timing | Only during /project-init | As needed during development |
